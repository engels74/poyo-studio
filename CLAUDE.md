# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Poyo Local Studio is a loopback-only SvelteKit 2 / Svelte 5 application running on Bun that drives the Poyo.ai image and video APIs. All state — SQLite database, media, logs, secrets — stays on the local filesystem.

## Essential Commands

Bun 1.3.14 is pinned in `.bun-version` and `package.json#engines`. `npm`, `pnpm`, `yarn`, and `node` are rejected by `tests/security/static-architecture.test.ts`; every script must be a `bun` / `bun run` invocation.

- `bun install --frozen-lockfile` — install dependencies.
- `bun run dev` — dev server on <http://127.0.0.1:5173>.
- `bun run build` then `bun run start` — production build and launcher; `scripts/start.ts` validates that `HOST` is `127.0.0.1` or `::1` before importing `build/index.js`.
- `bun run check` — `svelte-kit sync && svelte-check`. Run this after adding or renaming routes so generated `./$types` exist.
- `bun run lint`, `bun run format`, `bun run format:check` — Biome.
- `bun run test` — curated fast suite (unit, integration, reliability, static-architecture, performance).
- `bun test tests/unit/registry/ratio-resolver.test.ts` — single file.
- `bun test tests/unit/registry/ratio-resolver.test.ts -t "portrait"` — single test case.

Longer or gated suites:

- `bun run test:e2e`, `bun run test:security` — `scripts/test-browser.ts` runs `vite build`, then each `*.browser.ts` file serially under Playwright.
- `bun run test:performance`, `bun run test:restart` — serial (`--max-concurrency 1`); do not run concurrently with other suites.
- `bun run test:media-tools` — probes ExifTool / ImageMagick / FFmpeg and skips the image or video half when tools are absent.
- `bun run test:live` — real, billable Poyo calls; no-ops unless `POYO_LIVE_TESTS=1`.
- `bun run validate:registry` — offline registry/evidence consistency check.
- `bun run registry:evidence:refresh` — refetches official model sources and regenerates reviewed fixtures (network).
- `bun run test:smoke` — builds and exercises the production server end to end.

Bare `bun test` discovers every `*.test.ts`, including the host-tool suite that `bun run test` excludes. The `.browser.ts` and `.live.ts` suffixes deliberately keep those files out of Bun's default discovery.

## Architecture Overview

**Composition root.** `getPlatformServices()` in `src/lib/server/platform/runtime.ts` is a memoized singleton owning app paths, the SQLite handle, settings repository, API-key manager, JSONL logger, public-IPv4 guard, pricing service, and media-tool readiness. Server code resolves these from it; do not open a second `Database`, logger, or secret store.

**Request lifecycle.** `src/hooks.server.ts` `init()` starts the job and cleanup workers. `handle` acquires a maintenance-gate writer permit for every non-read method (returning 503 `maintenance_frozen` when storage maintenance holds the gate) and injects the stored default theme into the HTML before hydration.

**Persistence.** `bun:sqlite` with WAL and `foreign_keys=ON`, opened by `src/lib/server/platform/database.ts`. Migrations live in `/migrations` (outside `src/`), are checksummed when applied, and startup preflight rejects any database whose migration identity or canonical schema signature diverges from the registered chain.

**Poyo API access.** All outbound traffic goes through `createPoyoClient()` in `src/lib/server/poyo/factory.ts`, which builds a `PoyoTransport` with retry/backoff, redacted logging, and a pre-request public-IPv4 guard.

**Storage layout.** `resolveAppPaths` places everything under `<repo>/data` unless `PLS_APP_DATA_DIR` is set, creating directories at mode 0700. Media file access goes through `src/lib/server/media/filesystem-boundary.ts` and `resolvePathWithin`, which reject symlinks and paths escaping the configured root.

**Model registry.** `src/lib/features/registry/image-registry.ts` and `video-registry.ts` are hand-maintained catalogues checked against committed evidence JSON in `src/lib/features/registry/evidence/`. `src/lib/server/registry/repository.ts` seeds them into SQLite during platform startup.

## Project Boundaries

| Path | Rule |
| --- | --- |
| `src/lib/server/**` | Server-only. Never imported (except `import type`) from `.svelte` files, `src/hooks.client.ts`, or `src/lib/features/**`. |
| `src/lib/features/**` | Browser-safe domain logic, contracts, and registry data shared by loaders, API routes, and components. |
| `src/lib/components/**` | Svelte 5 runes components grouped by area: `ui`, `shell`, `studio`, `library`, `gallery`, `settings`. |
| `migrations/` | Append-only; imported by `src/lib/server/platform/database.ts` via a relative path. |
| `src/lib/features/registry/evidence/*.json` | Generated by `scripts/refresh-registry-*.ts`. Regenerate rather than hand-editing. |
| `data/`, `build/`, `.svelte-kit/` | Gitignored runtime and generated output. |

## Common Change Workflows

### Add a database migration

1. Create `migrations/000N-<name>.ts` exporting a `Migration` with the next strictly increasing `version`.
2. Register it in the `migrations` array in `migrations/index.ts`.
3. Bump `DATABASE_SCHEMA_VERSION` in `src/lib/server/platform/version.ts` — `tests/integration/database/migrations.test.ts` asserts the last migration version equals it.
4. Run `bun test tests/integration/database`.

Never edit a shipped migration's `sql`: the checksum stored in `schema_migrations` stops matching and existing databases refuse to open. Add a follow-up migration instead.

### Add a mutating API route

1. Create `src/routes/api/<path>/+server.ts` and read the body with `readSameOriginJson` from `$lib/server/platform/request-security`, which enforces origin, `sec-fetch-site`, content-type, and size limits.
2. Resolve dependencies with `await getPlatformServices()`, and convert failures with `operationsHttpError` from `$lib/server/operations/http` so responses keep the `{ error: { code, message } }` shape.
3. Mutating methods automatically hold a maintenance writer permit. Only routes that themselves perform storage maintenance opt out in `requestRequiresWriterPermit` and take their own exclusive lease — see `src/routes/api/settings/logs/+server.ts`.
4. Run `bun run check` and `bun test tests/unit/settings/routes.test.ts`.

### Change the model registry

1. Edit the entry in `src/lib/features/registry/`.
2. Run `bun run registry:evidence:refresh` (network) to refresh official sources and reviewed fixtures.
3. Run `bun run validate:registry`; it fails on inventory, provenance, normalization, or conditional-rule drift.
4. Run `bun test tests/unit/registry`.

## Critical Gotchas

- `Bun.spawn`, `Bun.spawnSync`, `Bun.which`, and `Bun.secrets` are banned in `src/**`. Subprocesses use `execFile` from `node:child_process` with an argument array and no shell — follow `src/lib/server/media/media-sanitizer.ts`.
- `process.platform` and `node:os` are banned in `src/**`, as are host-specific user-facing strings (`macOS`, `Windows`, `Keychain`, `storage-root`, `open-folder`, …). Keep shipped UI platform-neutral; credentials always use the file-backed secret store.
- Runes only: `export let` and `on:click=` are rejected in `src/**/*.svelte`. Use `$props()`, `$state`, `$derived`, and lowercase DOM handlers such as `onclick`.
- Every `createPoyoClient({ … })` call site must pass `publicIpv4Guard: platform.publicIpv4`, and `new PoyoClient(...)` / `new PoyoTransport(...)` may only appear in `src/lib/server/poyo/factory.ts` and `transport.ts`. Both rules are statically enforced.
- `src/**` must not reference the `tests/` tree by relative or aliased path. Test-only harnesses belong in `tests/helpers/`.
- prek's `no-commit-to-branch` hook blocks direct commits to `main`; work on a branch. Commit messages are validated as Conventional Commits.

## Testing and Validation

- `tests/unit/**` mirrors `src/lib/**` by domain. `tests/integration/**` uses real SQLite plus the mock Poyo servers in `tests/helpers/`. `tests/e2e/*.browser.ts` drives the built application with Playwright.
- Several suites are *static* tests that assert on source text — `tests/security/static-architecture.test.ts` and `tests/unit/settings/routes.test.ts` check imports, route inventories, and exact user-facing strings. Renaming a symbol, route, or label breaks them; update the assertion in the same change.
- Before finishing a source change run `bun run format:check && bun run lint && bun run check && bun run test`, mirroring the hook chain in `prek.toml`. Add `bun run validate:registry` for registry edits and `bun run test:e2e` for UI flows.
